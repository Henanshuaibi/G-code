# G code 0.13

基于 [anomalyco/opencode](https://github.com/anomalyco/opencode) 的非官方 Android 移植原型。使用 OpenCode 2.0.32 原版 Core / SDK 执行会话、模型请求和工具；Android 容器、手机界面、附件与生成任务由此适配包提供，与官方团队不存在隶属关系。

## 安装与使用

- Android 11（API 30）以上、arm64-v8a；以 iQOO 13 为目标，未做手表适配。
- APK 内置 Android Node.js 与 SDK，无需打开 Termux、电脑或远程后端。首次启动会解压依赖；AI 使用你配置的联网 API，不是本地模型。
- 本版包名仍为 `cn.g.opencode`，沿用 0.1～0.12 的签名。覆盖安装；旧服务的地址、模型与加密密钥按原服务标识保留迁移。
- API 设置支持多个服务。每个服务分别填写地址、接口类型、API Key，以及对话、生图、视频模型列表；每行一个准确模型 ID。每个服务至少填写一种模型。空白密钥保留该服务原密钥，新服务不会借用其他服务的密钥。
- 对话通过 Chat Completions 或 Responses 接口。顶部模型按钮按服务分组切换，不同服务的同名模型保持独立。模型需要支持工具调用；图片和 PDF 还需要所选模型与服务支持对应输入。
- 新建空白对话会复用当前项目已有空白对话，防止连点重复创建。首条消息后 SDK 使用 AI 生成中文标题，额外调用一次模型。旧版“新会话”继续聊天时恢复自动标题；手动标题保留。侧栏对话右侧 `⋯` 可改名、删除。
- 删除对话会停止其 AI 回复并删除记录与修改快照，保留项目文件；已经提交的生成任务仍保留在创作页。
- 项目 ZIP 导入、导出入口和原生桥接已删除。现有项目与文件保留，仍可使用私有工作区、文件预览与修改页。

```sh
cp ~/G-code-0.13.apk ~/storage/downloads/
```

## 会话管理、token 与 ChatGPT 登录（0.13）

- 侧栏“批量删除对话”：勾选多段，或全选当前显示列表（最近最多 100 段），在底部面板确认后逐项删除。显示成功与失败数量，某段失败不会阻止其他所选项。停止被删除会话的任务，清除对应草稿；未选会话、项目文件和已提交的生成任务保留。删除不能撤销。
- 会话列表、聊天顶部、每条 AI 回复显示 token 数，点击顶部或回复下方用量可展开输入、输出、推理、缓存读写。使用原版 SDK 的统计字段；总量包含 SDK 记录的自动标题、上下文压缩等额外请求，不受消息分页影响。未返回单条用量显示“用量未返回”；累计仅包含已上报部分，不代表账单或订阅剩余额度。
- 侧栏“ChatGPT 账号”或 API 设置中的登录入口 → Continue with ChatGPT → 系统浏览器在 OpenAI 官方页面完成登录与订阅授权 → 返回 G code，点击“检查登录结果” → 选择“ChatGPT 订阅”分组下的模型。可取消待完成登录、重新登录、退出本机账号。
- 使用原版 SDK 的 `chatgpt-token-sharing` OAuth，包括 PKCE、state、nonce、ID token 校验、凭据持久化和续期；首次动态注册显示 G code。浏览器回调仅监听本机回环地址。不需要提供密码给 G code，也不读取 Termux/Codex 的登录文件。OAuth 凭据由 SDK 保存在应用私有目录，与 Android Keystore 加密的手填 API Key 存储不同；不通过界面或中转站输出凭据。
- 登录后使用官方 Responses 路由，可用模型与额度受账号、套餐和官方授权限制；目录中出现模型不保证该账号能调用。生图、视频继续使用独立的 API 服务，这个订阅授权入口不为创作接口提供额度。退出账号先停止运行中的任务，删除本机保存的 ChatGPT 授权，保留会话和其他服务配置。

官方依据：[注册与登录](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)、[订阅授权接口限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。自动测试覆盖原 SDK 授权链接、错误 state 回调、取消、测试凭据加载/退出、官方路由与密钥不外露；没有使用真实账号完成 OAuth、刷新凭据或验证订阅额度扣除，Android 浏览器跳转与回跳仍待真机验证。

## 下载、附件与预览缓存优化（0.12）

- 生成视频下载改为流式写入私有临时文件，完成后再原子替换最终文件，不再把整个 MP4 放入内存。下载中断、超限或文件头不符时删除半成品，保留已有完整文件；仍限制单视频 100 MB。
- 普通附件逐项读取并检查合计大小，超限即停止，不再并行读取完所有附件后才拒绝。停止发送时，取消信号会传入附件读取；视频缩略图校验后不再长期保留其字节缓冲。
- 历史图片和截图的预览元数据最多缓存 512 项，删除会话同步释放对应记录。已完整写入的同内容预览复用，截断文件重新写入；新预览先写临时文件再原子替换，避免读取到半成品。

自动回归覆盖真实本地 HTTP 视频下载的完整字节、中断、超限、错误内容、空响应、写盘失败，以及附件提前拒绝、取消和预览缓存释放。MP4 文件头检查不等于视频编解码或播放验证；未测量真机内存、耗电或帧率提升。

## 刷新与内存优化（0.11）

- 流式回复只重建变化的消息卡片；未改变的历史消息、图片和工具详情复用现有节点。更新的消息保留已展开的详情状态，避免每次回复都把详情收起。生成媒体卡片随当前列表清理缓存。
- 历史图片与生成图片使用延迟加载、异步解码。应用界面隐藏时停止安排轮询，返回前台立即请求刷新；本地引擎、手机控制、超时保护和生成任务仍继续运行。
- 空闲轮询间隔从 1.8 秒调为 3 秒；任务中仍为 450 毫秒。会话列表自动刷新至少间隔 5 秒，打开侧栏仍立即加载。仅运行中或有待确认操作时查询权限列表。
- 项目修改快照保留在磁盘，打开修改页时按需读取，不再为每段会话长期保留一份项目全文在内存中。

专项测试使用真实 HTML 节点树适配器运行生产节点更新代码：500 条消息未变化时 0 次节点操作；仅一条消息变化时只构建 1 个新节点，执行 1 次插入与 1 次移除，并验证顺序、旧节点状态和缓存释放。它不是 Android WebView 的帧率、耗电或触控测试；没有声称实测提升百分比。

## 本轮问题检查与修复（0.10）

- 同一会话从准备消息开始即占用提交状态，8 个并发请求只受理 1 个。停止会取消未提交的准备工作，并等待准备结束后中断 SDK，避免停止后迟到启动；准备失败会释放会话。
- 长对话先读取最近 150 条，顶部可加载更早消息。使用原版 SDK 的分页游标，合并显示已读取的历史；不会停留在最早的 150 条而漏掉后续回复。
- 聊天、文件、修改页的迟到响应核对当前页面，防止切换页面后又被旧请求覆盖。创建对话期间切换页面也不再被迟到结果拉回。
- 发送成功仅清除本次提交的草稿与附件；发送等待期间继续输入的内容、另一段对话的草稿、新增附件保留。删除附件的回调固定到原会话；提交中不再允许删除正在发送的附件。
- 本地 HTTP 请求按字节拼接后解码，避免中文或表情在分块边界变成乱码。任务已被 SDK 接收后，临时附件清理失败不再错误地提示“发送失败”。

验证使用真实 SDK、临时工作区与本地 HTTP 模型夹具，没有使用用户 API Key。原生选择器、第三方应用操作和页面触控效果仍需要手机实测。原签名与配置存储方式保留。

## 外观与界面

应用显示名称为 `G code`，包名和原签名保持 `cn.g.opencode`，可覆盖旧版 OpenCode Mobile。关于页继续标注其基于 OpenCode 的非官方移植身份。

默认白底黑字。在侧栏“外观与界面”切换白底黑字、深色、跟随系统或自定义；自定义可填写背景色、文字色、按钮/强调色（`#rrggbb`），并调节 12～22 的字号和 0～24 的圆角。文字和背景太接近时提示换一组颜色，防止把界面调到看不清。

点击“预览”查看效果，再点“保存外观”；关闭面板会撤销未保存预览。“恢复白底黑字”一键重置。外观独立保存在本机 UI 偏好中，重开应用保留，不修改 API、模型、会话，也不重启引擎。对话、代码区、侧栏、底部面板、表单和状态栏一起变色；系统文件选择器仍使用系统样式。“跟随系统”读取 Android 实际的夜间模式，而非仅依据固定浅色 Activity 中的 WebView 媒体查询；见 [WebView 深色主题说明](https://developer.android.com/develop/ui/views/layout/webapps/dark-theme)。实际手机上的颜色、字号、预览撤销和系统跟随效果尚待实机确认。

## 照片、视频抽帧与文件附件

点击输入框左侧加号，在底部面板选择“选择照片”“选择视频（抽帧）”或“选择文件”，再使用系统文件选择器。无需授予整个相册或存储目录权限。显示逐项处理进度与错误；部分文件失败不会丢弃已成功的附件，处理中暂停发送。进程退出后保留成功项，并提示未完成的处理已中断。选择后显示缩略图与文件名，可以移除；点击发送才提交给模型，只添加附件也可以发送。

照片在本机解码、按 EXIF 方向旋转，最长边缩至不超过约 2048 像素，转换为 JPEG；透明 PNG 尽量保留 PNG，超限时转成白底 JPEG。GIF 动画仅取首帧。HEIC/HEIF、AVIF 等取决于 Android 系统解码能力，不支持时明确提示转换。原图超过旧版 10 MB 限制不再直接拒绝，但仍限制像素尺寸，避免内存过大；不是无损原图上传。

视频原文件最多 100 MB，在本机读取并抽取最多 8 张、最长边约 1280 像素的 JPEG 画面。AI 收到带时间点的抽样图片和说明，不接收原视频，也不包含音频；不能据此理解整段连续动作、语音或音乐。多个视频与照片同发时，画面总数最多 16 张，必要时进一步均匀减少各视频抽帧数。所选模型和服务需要支持图片输入。

每条最多 8 个源附件，处理后的媒体与文件合计最多 20 MB。普通文件单个最多 10 MB，UTF-8 文本/代码最多 256 KB；支持 PDF、TXT、MD、JSON、CSV 等。Office 文档、压缩包等二进制文件暂不解析，请转换成 PDF 或文本。图片/PDF 经原版 SDK 作为媒体发送，文本和视频说明作为附件文本发送，不是只发送文件名。旧版已失败的 HEIC/视频附件请先移除，再重新选择。

原视频仅临时复制到私有目录供解码，抽帧结束即删除；发送任务被 SDK 接收后清除上传临时副本。SDK 对话数据库保留实际发送的图片、视频帧与文本，历史预览使用私有缓存。内容仅向你选择的服务发送。系统选择器、HEIC/EXIF 解码和视频编解码尚未实机验证；自动测试覆盖实际 SDK 到 HTTP 模型接口的照片/视频帧/PDF/文本传输。

实现依据 Android 官方 [系统文档选择器](https://developer.android.com/training/data-storage/shared/documents-files)、[位图采样解码](https://developer.android.com/topic/performance/graphics/load-bitmap) 与 [视频抽帧 API](https://developer.android.com/reference/android/media/MediaMetadataRetriever)。

## 生图与视频

服务设置将 `models`、`imageModels`、`videoModels` 分开保存。未配置生成模型时，工具明确提示配置，不把普通对话模型自动发送到生成接口，也不通过猜测模型名称重试收费请求。

可以在聊天里明确要求 AI 生图/生成视频，原版 SDK 通过 `generate_media` 插件提交；也可以通过加号或“创作”页手动指定服务、模型、描述和可选尺寸。生成结果在对话和创作页展示，可预览图片、播放 MP4，并使用系统文件选择器保存到手机。

- 图片：OpenAI 兼容 `POST /images/generations` JSON 格式，处理 `data[0].b64_json` 或 `data[0].url`；URL 结果下载到本机，跨域 CDN 不携带 API Key。每次一张，本机单图上限 20 MB。
- 视频：OpenAI Videos 格式，`POST /videos` 使用 multipart，`GET /videos/{id}` 查询，`GET /videos/{id}/content` 下载 MP4。可选 4 / 8 / 12 秒；尺寸可留空使用服务默认值。本机单视频上限 100 MB。
- 最多同时运行 3 个生成任务。视频显示远端任务 ID、状态和进度；重启后查询原任务，不重新 POST。查询/下载失败可刷新原任务。自动查询约 1 小时后暂停，可手动继续。
- 请求提交期间断开连接可能无法确认服务端结果，因此不自动再次提交。停止 AI 回复或删除对话不等于取消已经提交给生成服务的任务。
- 私有视频协议、Chat 流式生图、图生图和参考图生视频尚未适配；提供接口文档后可增加适配。模型及服务本身必须有对应能力，本机客户端不能把纯对话模型变成生成模型。

实现依据 OpenAI Docs 的 [Image generation](https://developers.openai.com/api/docs/guides/image-generation) 和 [Video generation](https://developers.openai.com/api/docs/guides/video-generation)。这些是兼容协议的实现参考，不表示任意中转站都支持。

## 手机控制

侧栏“手机控制”→打开系统无障碍设置→手动启用 G code 手机控制→返回刷新→阅读页面与截图发送说明→为当前会话开启全设备界面控制。升级后需在系统中关闭再开启一次服务，让 Android 重新加载截图与手势能力。不限定美团或预设名单；可以跨应用完成任务。

`phone` 工具通过原版 SDK 执行：`apps` 枚举可启动应用名称/包名；`open` 打开指定包；`read` 观察当前前台页面（包括桌面和系统界面），返回文字、控件、父控件、位置和页面 token。支持 `click`、`long_click`、`type`（普通文本最多 4000 字）、`scroll`。缺少控件时 `screenshot` 返回真实 JPEG 图片给模型，再用 `tap`、`long_press`、`swipe` 按图操作。坐标为截图的 0～1 比例；每步重新观察验证。全局支持 `back`、`home`、`recents`、`notifications`、`quick_settings`。截图需要支持视觉输入和工具调用的模型。

修复了页面变化误判：广告刷新、倒计时和普通内容事件不再直接使所有控件失效。每次节点操作前刷新并比较目标的文字、位置及身份；换应用、换窗口、旋转屏幕或目标改变时要求重新读取。观察最长保留 2 分钟以容纳模型推理；截图坐标还会重新核对可操作控件布局，布局改变需重新截图。此修复尚未在用户美团“拼好饭”页面实机复测。

单次最多 15 分钟 / 300 次工具请求，不跨重启保留。悬浮停止按钮、通知操作、应用内停止入口可撤销；停止回复、切换会话、引擎关闭也会撤销。异步截图与手势完成回调重新校验本次授权；已开始的手势最多 2 秒，停止不能撤回已发生的点击。截图只在工具调用时采集，不持续录屏；原生临时文件交给 SDK 后删除，截图作为对话的一部分存储，界面以私有图片预览呈现。

这是普通 Android 无障碍界面控制，不是 root：无法绕过锁屏、其他应用私有目录或受保护页面的截图限制。密码、系统权限确认、最终付款下单由你接手；普通搜索、编辑、跨应用导航等不按固定应用封锁。应用是否暴露控件、系统是否允许手势，以及 iQOO 的后台运行策略，都仍需真机验证。

实现依据 Android 官方 [AccessibilityService](https://developer.android.com/guide/topics/ui/accessibility/service)、[ScreenshotResult](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.ScreenshotResult) 与 [package visibility](https://developer.android.com/training/package-visibility/declaring)。只查询带启动入口的应用，不申请全部安装包或整个存储目录权限。

## 操作停顿与恢复（0.6）

- 无障碍控件遍历、布局核对、截图压缩移到串行后台线程，避免复杂页面阻塞主线程与停止按钮。普通 read 不再额外遍历整个页面布局，控件签名仅查找有界的首个标签。遍历期间检查授权与请求截止时间；停止立即撤销授权并取消截图/手势回调等待，不排在页面读取队列后。
- 原版 SDK 的实际执行事件投影为“等待模型响应 / 正在思考 / 准备操作 / 执行工具 / 等待确认 / 服务重试”等状态，在聊天顶部和手机控制悬浮条显示。悬浮状态文字可点击返回 G code 处理确认；停止按钮单独保留。等待用户确认时不会按模型无响应处理，多个并行工具中其他工具完成也不会覆盖待确认状态。
- 普通界面请求最长 20 秒，提交任务最长 40 秒；超时会真正取消 fetch 并恢复轮询，不自动重复发送。提交超时不代表任务未受理，应先查看状态与结果。模型/工具连续 8 分钟没有实际进展会请求 SDK 停止并撤销手机控制；持续输出思考内容会更新活跃时间，不限制正常多步任务的总时长。
- 点击聊天顶部状态或侧栏“任务状态与恢复”，可停止当前任务；如果引擎无响应，可以通过底部面板确认重启引擎。会话、项目、API 设置和密钥保留。重启会撤销手机控制，请先检查任务结果，再重新授权继续。停止不能撤回已经发生的点击。
- 自动回归包含本地 HTTP 接口完全不返回内容、请求实际被取消、状态仍可读取、SDK 中断后继续新请求，以及不重放先前手机动作。它不是在手机上复现了原生卡顿；iQOO 后台策略和真实第三方应用的响应仍待实机验证。

Android 线程处理依据 [官方线程指南](https://developer.android.com/topic/performance/threads)。没有申请忽略省电策略或新增后台权限。

## 搜索与授权修复（0.7）

- 修复单次请求超时或单个工具中断时，IPC 自动发送整段会话 `stop` 导致授权丢失的问题。现在只发带原始 requestID 的 `cancel`；原生请求取消标记、截止时间、会话和授权代次在执行前与遍历期间核对，已经取消或超时的请求不能排队后又执行。取消一次请求不延长或重新获得会话授权，显式停止、切换会话、服务断开、15 分钟到期和 300 步限制仍有效。
- `onInterrupt` 按 Android 的无障碍反馈中断回调处理，不再等同于服务断开。服务真正解绑/关闭仍撤销授权。`phone status` 返回当前会话是否授权及原因；错误结果携带真实授权状态，操作失败不能再一律解释为“授权失效”。
- `read` 优先返回当前聚焦编辑框 `focusedNode`，防止复杂页面截断导致搜索输入框漏掉；输入法窗口成为活动窗口时，找到仍持有输入焦点的应用窗口。可输入能力同时检查原生 editable 标记和实际 SET_TEXT 动作。
- 新增 `focus` 与 `submit`。搜索流程应为：打开搜索页 → read 找真实输入框 → 必要时 focus → type 填关键词 → read 核对文字 → 点击页面搜索按钮，或对支持 IME_ENTER 的聚焦输入框 submit → read 验证结果。type 成功不代表已搜索，submit 被接受也不代表已取得搜索结果；不支持时使用截图定位键盘上的搜索键。不要盲目重放结果未知的输入或点击。
- 自动验证：真实 IPC 超时仅取消原请求且状态仍授权；生产 Java 请求取消/到期不撤销会话但拒绝迟到执行；旧排队请求不能借新授权执行；真实 SDK 本地模型夹具覆盖输入超时后的状态确认、重新读取并提交搜索，不重复输入。该夹具不代表淘宝“闪购”已实机验证。

官方依据：[onInterrupt](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#onInterrupt()) 是反馈中断；[ACTION_IME_ENTER](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo.AccessibilityAction#ACTION_IME_ENTER) 用于具备输入焦点的可编辑节点。覆盖更新后重新开一次无障碍服务，以加载交互窗口读取标记，再为会话授权。

## 数据与边界

API Key 由 Android Keystore 加密保存；运行时只交给对应服务。正文、附件、项目、任务和媒体文件保存在应用私有目录，正文不额外加密。卸载或清除数据会删除它们。生成媒体可使用“保存到手机”另存。

本地界面与引擎使用随机访问路径和随机回环端口，不监听局域网；设备工具使用独立随机令牌的私有进程管道。项目外目录访问在 SDK 会话权限中拒绝；上传与生成文件不放在项目中。

当前不提供完整 Git、交互终端、MCP 配置、语音输入或朗读。文件工具使用实际 SDK；shell、CodeMode execute 与 question 禁用。文件预览最多 1 MB，修改快照最多 20 MB / 2000 文件，忽略依赖与构建目录；修改页是本次任务前后的文本比较，不是 Git 工作树。

中文用于操作说明，保留 OpenCode、API、Git、接口名、模型 ID、路径、代码和命令等原文。
