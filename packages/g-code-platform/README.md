# G Code 平台余额后台 0.2（本地试用实现）

提供账号、卡密余额、模型按量计费和多个中转站的优先级主备路由。Android 客户端仍使用原 OpenCode SDK / Core 在本机运行项目和工具，后台不运行用户项目。**这是小规模试用代码，不是已经验证的正式商用服务。**

只销售两个展示模型：**GPT 6.1 Sol**、**DeepSeek V4.1 Flash**。`gcode-sol` 和 `gcode-flash` 是本平台产品标识，**不是上游 model ID**。初始数据库没有真实上游、凭据或价格，两个产品默认禁用。上游实际 ID 必须由运营者从其接口或文档确认后配置映射，代码不会猜测。

## 这是你的模型销售服务

用户购买你在其他平台销售的卡密，在 G Code 注册/登录、兑换为余额、选择你提供的模型编程；你在管理界面设置销售价，统一接入多个供应商。后台记录收入、采购成本和估算毛利。用户不需要自行购买 API、不填写上游 Key、也不切换中转站。盈利取决于你配置的售价、采购价和实际运营成本，代码不会编造市场价或保证利润。

正常用户只连接你的统一后台。运营方在 Android `platform-release.json` 的 `base_url`（或构建环境变量 `GCODE_PLATFORM_URL`）填写你的 HTTPS 域名，然后构建安装包，详见 [`../android/README.zh.md`](../android/README.zh.md)。这不是让每个用户配置地址。APK 是客户端，账号/计费/密钥/路由服务仍需要实际运行在你的服务器；仅安装 APK 不会自动产生一个对外可用的平台。

## 思考档位和 Fast（Android 0.19）

1. 在「渠道与映射」编辑渠道：选择已确认的 Fast 上游服务档（`priority` / `fast` / `ultrafast`，默认未确认）；在高级设置填写站点明确支持的思考取值。界面会加入对应协议的 `reasoning_effort` / `reasoning` 和 `service_tier` 参数声明。保存能力变化后，重新确认此渠道的模型映射。
2. 在「销售价格」分别设置该产品标准价格和 **Fast 售价**；在模型映射分别设置标准采购价和 **Fast 采购价**。全部使用四个互不重叠的 token 计费类别和既有币种/汇率规则。没有 Fast 价格不会借用标准价，不会自动编造差价。
3. 客户在聊天顶部「思考」选择支持的档位、标准／Fast，并查看 Fast 报价。对外平台协议以 `service_tier: priority` 表示购买 Fast，后台映射到渠道实际配置的值；默认/标准在已声明支持服务档的渠道显式发送 `default`。其他厂商的非标准加速协议暂不支持。
4. 不支持组合直接拒绝，不会降低档位或跨产品替换。Fast 计费使用独立销售/采购快照，重试成本继续独立记录。账单 `price_snapshot` 包含 `reasoning_effort` 和 `service_tier`，尝试 `cost_snapshot` 保存实际上游服务档。
5. 最终 usage 同时报告的服务档如果与所购 Fast 不符：未开始交付回答则返回明确错误并释放预留；已开始正文/工具后保留预留、标记 `needs_review`，不自动扣 Fast 费用，也不静默重跑。采购成本不伪造为确认数值，管理员按上游账单核对。`priority`/`fast` 视为同一服务档别名，`ultrafast` 需精确匹配。上游没有回报服务档时，依赖管理员确认的协议承诺，不能由软件据此证明加速生效。

运行迁移或正常启动会应用 `003_fast_prices.sql`；新增列默认空值，不改变旧账本，不自动开启真实渠道能力。请先备份数据库及主密钥。当前本机试用服务仍不进行真实付费验证。

## 技术与许可证

Node.js 24+（本机实际使用 Node 26.3.1）、内置 `node:sqlite`、HTTP、crypto；无新增运行时 npm 依赖。SQLite WAL + 单服务进程适合小规模试用，无需 Redis、消息队列或容器。不要用 PM2 cluster、多个副本或共享网络文件系统访问这个数据库。

仓库及此包为 MIT，保留 `LICENSE`、上游 OpenCode 版权和 Android 的运行时许可文件。此实现不会改变其他组件的许可证，也不能代替上游服务商对转售、品牌名称和数据处理的授权；代码许可不提供服务商转售授权。

## 本地启动（不要使用真实上游做自动测试）

```sh
cd ~/opencode-mobile/packages/g-code-platform
npm test
cp .env.example .env
mkdir -p data
chmod 700 data
# 生成主密钥，私下填入 .env；不能提交到 Git 或发进聊天
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
chmod 600 .env
```

编辑 `.env`：

- `GCODE_MASTER_KEY`：上一步生成的 32 字节随机主密钥 Base64。加密上游 Key 和可导出的未使用卡密，另用于会话摘要、请求摘要。须单独备份，丢失后无法恢复加密凭据和未使用卡密；更换密钥会使已有会话失效。第一版不提供自动密钥轮换。
- `GCODE_DAILY_COST_LIMIT_MICROS`：你决定的每日采购成本上限，整数微 CNY。示例故意没有填市场价或预算。
- 本机模拟服务可设置 `GCODE_PRODUCTION=false`、`GCODE_PUBLIC_ORIGIN=http://127.0.0.1:8787`，需要 HTTP 模拟上游时再设置 `GCODE_ALLOW_LOOPBACK_UPSTREAM=true`。生产模式要求 HTTPS 公共地址，并禁止 HTTP 模拟上游。
- `GCODE_DB`、监听地址、端口可按需修改。客户端平台地址是后台对外根地址，例如 `https://your-domain.example`，不要加 `/v1`。

```sh
npm run migrate
# 私下用编辑器在 data/admin-password.txt 写入至少 10 字符密码，文件权限 600。
chmod 600 data/admin-password.txt
# .env 中设置 GCODE_ADMIN_USERNAME 和 GCODE_ADMIN_PASSWORD_FILE 后执行：
npm run admin
# 初始化成功后移走/删除一次性管理员密码文件，移除对应环境变量。
npm start
```

迁移按 `migrations/*.sql` 的顺序自动执行并记录版本，也可单独执行 `npm run migrate`。初始化命令只允许在没有管理员时创建首个管理员，不会覆盖已有用户、重置密码或升级同名账号。第一个初始化的管理员同时是唯一最高管理员；已有数据库迁移后会将最早的管理员标记为最高管理员，不清空用户或账本。普通注册始终是普通用户。最高管理员可在「用户」中授予/撤销普通管理员权限，需填写原因；权限变更撤销该用户现有会话。其他管理员不能修改最高管理员权限、账号限制或余额。管理员也从零余额开始，自用必须充值或有原因地人工入账；照常记录用量、采购成本和扣款。

访问后台根地址，使用同一个账号系统。普通账号只显示自己的资料、余额和账单；管理员额外显示用户、卡密、渠道、价格、用量/成本与审计。

## 配置真实渠道、两个模型与价格

1. 登录管理员 → **渠道与映射 → 添加上游渠道**，填写名称、HTTPS Base URL、API Key、协议、优先级（数值小的优先）、启用状态、超时及并发上限。Base URL 含 `/v1` 等 API 根路径，不能包含查询参数、账号密码或最终 `/chat/completions` 路径。
2. 按服务商文档或已获许可的测试结果勾选流式、函数工具和图片识别能力；默认均不勾选。超时、并发、可选参数、用量字段放在高级设置，备注/文档链接选填。不能仅因“OpenAI 兼容”就全部勾选。`input` 默认 `["text"]`，确认识图后才加入 `"image"`。
3. 可主动点击 **读取 /models 元数据** 获取该渠道返回的 ID；这不是推理测试，也不能证明流式/工具/用量能力。若上游没有标准 `/models`，按其文档手工确认。页面不会自动发起真实推理。
4. 在渠道下为目标产品从已读取列表选择或填写**上游实际 model ID**、启用状态、采购价及可选备注；确认后才勾选“已从上游确认”。每个产品可配置多个渠道，每个渠道有独立 ID 映射与采购价。更改地址、Key、协议、能力或用量口径后，会清除映射验证状态，需要重新确认。
5. **销售价格** 中为两个产品分别选择客户端协议、确认的最大总输入和最大总输出（包括推理输出），按“元／百万 token”填写四类价格，再启用。价格全空可保存未配置状态；0 表示明确免费，后台转换为固定精度整数。后台只有已验证、采购价完整且协议相同的渠道才可用。G Code 客户端要求流式和工具能力；否则不会列为可用。
6. 调整 **用量与成本 → 每日采购成本上限**。用户 RPM / 并发可在“用户”中设置。渠道连续三次可重试失败冷却 30 秒，之后有机会恢复；成功清零失败次数。

示例结构只描述字段，数值须自己确认；不是推荐的价格或真实模型能力：

```json
{
  "stream": true,
  "tools": true,
  "input": ["text"],
  "params": ["temperature", "top_p"],
  "output_parameter": "max_tokens",
  "reasoning_efforts": []
}
```

Chat 用量口径示意（不代表你的站点确实这样返回）：

```json
{
  "input": "prompt_tokens",
  "output": "completion_tokens",
  "cache_read": "prompt_tokens_details.cached_tokens",
  "cache_write": null,
  "input_includes_cache": true,
  "output_includes_reasoning": true
}
```

Responses 常见字段为 `input_tokens`、`output_tokens`、`input_tokens_details.cached_tokens`；必须实际核对。字段相对于每次返回的 `usage` 对象。没有缓存读/写类别时用 null，代表该类别不单独计费；配置了路径但上游未返回合法整数时，视为用量不可靠，不能悄悄补零。

`input_includes_cache=true`：从总输入中扣出缓存读/写后，分别计价，避免重复。false：普通输入字段已经不含缓存，与缓存类别相加。总输出必须包含推理 token；推理类别暂不额外计价，以免重复收费。暂不支持音频、按图片张数/像素另收费、固定请求费、搜索/托管工具费等其他采购类别；图片仅支持已包含在 input usage 的 token 计价；这些渠道不要启用本产品映射。

价格结构，四类均须是明确配置的非负整数：

```json
{
  "currency": "CNY",
  "input": null,
  "output": null,
  "cache_read": null,
  "cache_write": null
}
```

null 表示尚未配置，不能启用计费；0 表示运营者明确设置该类别为零价。每个数字的单位是 **微货币 / 百万 token**，1 CNY = 1,000,000 微 CNY。例如你自行决定某类别为 P 元/百万 token，则配置 P×1,000,000 的整数，不能直接填 P。销售币种固定 CNY；采购支持 CNY 或 USD。USD 必须额外配置 `fx_cny_micros`（1 USD 折合多少微 CNY），没有自动汇率，也没有代码内的市场价。采购原币金额与转换后的微 CNY 分别保存；每日成本与毛利使用 CNY。换价、换汇率、换映射不改变历史快照。

## 卡密、充值和自用

管理员“充值卡”中输入整数面额（微 CNY）与数量，生成并下载 CSV。卡密含 256 位随机值；数据库只用 HMAC 摘要查找，未使用卡密以 AES-256-GCM 加密以便授权导出。常规列表、审计和日志不显示完整卡密。兑换或作废后删除可恢复的密文，已用卡不能再导出/作废。CSV 是敏感发行凭据，请私下保管。

普通用户在 Android 的 **首页/侧栏 → 我的账号·卡密充值** 登录/注册并兑换，或直接在网页兑换。发行包由运营方预先绑定统一 HTTPS 地址，用户不填写地址或任何上游 API Key；之后从模型选择中选“平台余额”。后台自动选站，用户不能提交站点地址或上游 model ID。

余额不自动过期；无月费、续费、赠送、签到、分销、无限 token 套餐或在线支付。统一余额、两个模型单独定价。人工加减余额必须写原因，记录操作人，不得扣到已预留金额以下。每笔充值、人工调整和请求结算都有账本记录，用户可分页查询；账单接口同时返回当前可用/预留余额，每笔账本保留入账后余额。Android 选模型时先刷新并展示四类售价与版本；若无法核实最新平台报价，提示重试，原自填 Key 服务仍可选择。

## 计费、预算与失败处理

- 全程整数微货币，乘法用 BigInt，最后对**单次调用各类别合计**向上取整到一微货币。SQL 事务 `BEGIN IMMEDIATE` 检查余额与并发，预留后可用余额立即减少；完成按快照实际用量扣款并释放差额。
- 单次 HTTP 模型调用是结算单位；一个 OpenCode 工具任务可能包含多次模型调用，每次都有独立 ID 和账单。自动标题在平台模式使用本地标题，不隐含增加付费请求。
- `Idempotency-Key` 必须唯一；重复提交只返回已记录提示，不重新调用，不重复扣费，也不保存回答供重放。Android 本机转发器生成 UUID；SDK 平台模式禁止额外自动重试。用户明确发起的新任务使用新 ID。
- 为避免依赖未知 tokenizer，**请求前按管理员确认的最大总输入和本次最大总输出预留**，缓存输入使用三类输入中的最高费率。文字 payload UTF-8 字节数加固定 4096、每条消息 32 和每个工具 128 的开销，作为保守入口长度检查；这不是实际 token 估算，也不用于用户扣费。必须按上游确认的上下文和“最大输出含推理”限制配置模型。真实上下文不符或用量超界会进入核对，不追加透支扣款。
- 销售与采购分别预留、分别记账。重试的采购尝试单独记录，只有一次成功调用的实际用量向用户结算。所有尝试计入每日采购预算。每个尝试按 UTC **尝试开始日**记入成本日，跨午夜仍归该日。
- 默认最多三个渠道尝试、总时限 60 秒；按优先级依次选择同产品、同协议且支持本次参数/功能的渠道。连接故障、超时、408/429/500/502/503/504、输出前损坏的流允许切换；其他 HTTP 错误直接返回。HTTP 200 包裹的 SSE 错误也检查错误类型/状态：参数、鉴权等永久错误不重试；明确的限流或暂时故障才允许切换；无法分类的上游错误停止并返回安全诊断。不会 GPT→DeepSeek 或反向替代。
- 输出正文、推理文本或工具调用开始前，先持久化 emitted 标记。之后不得静默重跑。仅 assistant role 或 response.created 的元信息可在尚无实际输出时丢弃并换站。SSE 结束标记在结算后才交给客户端。
- **没有可靠 usage 不编造 token**。流已输出而最终用量缺失/非法/超界或多次报告相互冲突：`needs_review`，该次预留继续显示在“预留”，管理员按供应商凭证补用量结算（不得超过原预留）或退款。无输出/非流式尚未交付回答：返回失败并释放用户预留，不交付虚假成功。
- 连接失败不保证供应商未计费，因此没有可靠采购用量时，采购记录标记 `upper_bound`，用预留上限暂占当天成本，usage 为空，**不是实际 token，也不是自动扣用户的估算 token**。管理员可在“采购尝试与供应商账单核对”填实际用量或有依据的零用量，冲正成本；采购未知项存在时，毛利明确为估算。管理汇总分别显示 `actual_cost_cny_micros`（已确认采购成本）、`unknown_cost_upper_bound_micros`（未知采购成本上限）和 `active_reserved_cost_micros`（调用中采购预留）。`cost_cny_micros` 是已确认与未知上限的合计，估算毛利用此合计计算；活跃预留单列，不冒充实际支出。`billed_usage` 只合计用户已结算请求的四类用量；采购 token 列合计所有已知采购尝试（包含重试），与用户计费用量区分。汇总采购 token 列只合计已知用量，未知数量另列，不代表未知尝试真的消耗零 token。
- 每日采购预算是基于已确认的上下文/输出和采购价的保守预算，不是对失实上游账单的数学保证。供应商实际超限或价格/缓存口径不实会产生运营差额；不能向用户强行追加透支，需暂停渠道并核对。预算耗尽不会继续发送新尝试。
- 取消/超时/用户禁用会中止上游 HTTP。后台每 10 秒恢复超时活动记录；单进程重启在租约可接管后恢复遗留记录：无输出释放预留，有输出进入待核对。遗留采购按上限记未知成本。**不要直接清零数据库里的 reserved 字段**，请用管理员核对/退款保持账本一致。
- SQLite 单进程租约为 30 秒；进程被强杀后，重启可能需等租约过期。正常关闭会取消请求并删除自身租约。发送上游、输出和结算前校验租约；旧进程恢复时不能继续输出已被新进程恢复处理的请求。未确认用量的预留不会自动“过期扣掉”或无依据变成实际账单，试用运营必须定期处理待核对记录。

## 接口与能力边界

已检查本机 `@opencode/sdk` / `@opencode/ai` 2.0.32 的 Chat 和 Open Responses-compatible 实现，保留真实 Core 的模型/工具执行。平台分别提供 `POST /v1/chat/completions` 和 `POST /v1/responses`，不做两种协议之间的猜测转换。真实上游仍需按渠道验证。

- 支持 SSE、文字、函数工具定义、工具参数流和工具结果回传；Chat 强制 `stream_options.include_usage=true`，只采信空 choices 的最终用量块或有 finish_reason 的结束块；Responses 只读取终态 response usage，忽略中间进度块中的计数。后续非法或冲突的最终报告不会沿用先前计数结算。默认 `store=false`，不提供后台对话存储。
- 识图支持内嵌 PNG/JPEG/WebP/GIF 数据，保留真实图片字节并按 `capabilities.input` 路由。普通文字线路不会接收图片，不跨模型降级。图片最多 16 张、单张 10 MiB、合计 20 MiB；请求体最多 32 MiB。大于 2 MiB（或未声明长度）的请求全站同时最多 1 个，读正文限时 15 秒，避免多个图片正文一起占用大量内存。仅根据上游完整 usage 结算，入口字节检查排除图片 Base64，不把它当文字 token；预留仍使用完整输入上限。远程图片 URL、PDF/音频和未知图像字段拒绝。
- 渠道可选 `capabilities.output_parameter` 明确指定已确认的输出限制字段：Chat 为 `max_tokens` 或 `max_completion_tokens`，Responses 为 `max_output_tokens`。只有运营者配置才转换字段名，数值和含推理的限制不变；未配置则保留 SDK 原字段，不能猜测上游接受哪种写法。
- 可选 `temperature/top_p/parallel_tool_calls/...` 只路由到明确列入 `capabilities.params` 的渠道；思考强度还须在 `reasoning_efforts` 中。SDK Responses 会发送 `prompt_cache_key`，也可能自动发送 `include: ["reasoning.encrypted_content"]`，应确认上游是否支持这些字段，并在 `params` 中明确列出；不支持则明确报错，不伪装兼容。
- 尚未验证：Responses WebSocket、服务端 previous_response_id/后台作业、托管搜索/执行/图片工具、音频/PDF输入、任意厂商扩展。相关参数/输入会明确拒绝。原自填 Key 的功能不受此限制。
- 平台地址和上游地址不能通过普通用户模型请求传入。每个服务端地址只来自管理配置，HTTP 重定向不跟随。模型列表接口不暴露上游地址或凭据。
- 平台默认只保留账号、卡密摘要/未用卡密文、账本、价格快照、用量和受控诊断码。请求内容仅在转发期间存在内存，幂等摘要使用带密钥 HMAC；不写服务端日志/数据库。原 Android SDK 在本机保留会话，这是原功能，不等于后台保存内容。第三方服务商仍可处理数据，需另行核对其政策。

协议参考：[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Responses SSE](https://developers.openai.com/api/reference/resources/responses/streaming-events)。官方文档也指出中断的 Chat 流可能没有最终用量；没有用“兼容”字样替代渠道确认。

## 部署（只给出说明，不自动部署）

推荐单台服务器、一个 Node 进程、SQLite 本地磁盘和 HTTPS 反向代理。部署前先用模拟上游跑测试，完成真实服务商配置后再由你决定是否授权真实联调。

1. 复制此目录到服务器，安装 Node 24+，保留 LICENSE；无需安装服务端 npm 运行依赖。
2. 配置私有 `.env`、初始化管理员和迁移，设置数据目录 700、`.env`/密码/数据库文件 600，使用专门的非 root 账号运行。
3. 参考 `deploy/gcode-platform.service`；修改路径、用户和 Node 位置。只运行一个实例。健康检查 `/health` 不暴露配置。
4. 参考 `deploy/Caddyfile`；改成你的真实域名，`GCODE_PUBLIC_ORIGIN` 必须与浏览器使用的 HTTPS Origin 完全一致，不信任客户端自报代理头。反向代理不能记录 Authorization、Cookie、请求体或卡密响应，关闭第三方采集和正文审计，SSE 关闭缓冲。后台只监听 127.0.0.1，由 HTTPS 代理对外提供。
5. 首次小范围试用前，确认每个渠道的 ID、协议、流式、工具、用量/缓存、输入输出边界和销售/采购价格。当前实现不自动进行任何真实推理测试。
6. 备份 SQLite（推荐停服务后复制 DB，或使用 SQLite 的在线 backup 命令；不能只复制正在写的 DB 而忽略 WAL），同时分别保护主密钥和环境配置。恢复要使用匹配主密钥，并处理遗留预留。完整未使用卡密 CSV 不应进入源码或公共备份。

`GCODE_ALLOW_REGISTRATION=false` 可关闭新注册，不影响已有账号登录。浏览器会话使用 HttpOnly / SameSite=Strict Cookie，生产加 Secure，写接口检查 CSRF；Android 使用只保存在应用私有目录、权限 600 的平台会话凭据（不是上游 Key）。注销当前会话，禁用用户撤销所有会话并中止其当前平台调用。登录/兑换另有服务端频率限制。

## 注册防滥用与权限边界（0.17）

注册需先获取 `/api/register-challenge`，由客户端自动完成 14 位 SHA-256 工作量校验，再提交一次性 `registration_proof`。校验绑定连接来源、两分钟失效、使用一次即消耗，无法直接重放注册请求。普通注册提交 role/is_owner 等字段不能提升权限。网页与 Android 均已接入，不要求用户手算验证码。

校验申请全局每分钟 100 次、每连接来源 10 次；注册全局每分钟 30 次、每来源 5 次；登录/注册合计全局每分钟 120 次、每来源 30 次、每账号 12 次。密码哈希同时最多 2 个，可通过 `GCODE_AUTH_CONCURRENCY=1..4` 调整；超出直接 429，不建立无界任务队列。认证正文限 8 KiB，读取超时 10 秒，服务最多 100 条连接。以上值适合小规模试用，不是无限承载或完整 DDoS 防护。

当前来源采用真实 socket 地址，不盲信客户端伪造的代理头；通过反向代理时来源限制会共享代理来源，全局限制仍生效。扩大公开注册前，需要按实际部署配置可信代理来源识别及代理层限流，并评估外部 CAPTCHA / WAF。没有验证码服务账号时不会伪造外部验证成功。

账号密码使用 scrypt，至少 10 个字符；最高管理员也不绕过余额、成本及服务端鉴权。管理员修改余额、用户限制和权限均要求原因并保存操作人。最高管理员唯一且不能通过普通管理接口移交或降级。
